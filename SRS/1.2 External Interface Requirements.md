# 1.2. External Interface Requirements

This section outlines the hardware, software, and communication interfaces required to operate the Simple Workforce Manager system.

## 1.2.1. User Interfaces

The user interface SHALL be built with React 19.2.0 and Ant Design 5.28.0 UI Library, ensuring a clean, responsive layout accessible on desktop and mobile browsers over LAN connectivity.

### 1.2.1.1. General Interface Characteristics

The system SHALL provide a single-page application (SPA) architecture with client-side routing via React Router DOM 7.9.5. The interface SHALL utilize Ant Design component library for consistent UI/UX patterns including Layout, Menu, Typography, Avatar, Button, Space, Form, Table, Modal, and notification components. The system SHALL maintain persistent authentication state via JWT tokens stored in browser LocalStorage with automatic token validation on page refresh.

### 1.2.1.2. Role-Based Interface Components

**Admin Interface:**
- User management dashboard with CRUD operations table (StaffPage component)
- System-wide settings configuration panel (SettingsPage component)
- Complaints management interface with reply functionality (ComplaintsPage component)
- Feedback management interface with response capabilities (FeedbackPage component)
- Global dashboard with system overview (DashboardPage component)
- Profile management interface (ProfilePage component)
- Real-time chat interface (ChatPage component)

**Manager Interface:**
- Task assignment and management board (ManageTasksPage component)
- Task creation form with staff assignment dropdown and due date picker
- Attendance monitoring dashboard for all staff members (AttendancePage component)
- Reports review interface with filtering and search (ReportsPage component)
- Allowance management interface with creation and tracking (ManageAllowancesPage component)
- Complaints viewing and response interface (ComplaintsPage component)
- Feedback viewing and response interface (FeedbackPage component)
- Profile management interface (ProfilePage component)
- Real-time chat interface (ChatPage component)
- Personal settings configuration (SettingsPage component)

**Staff Interface:**
- Personal task list with status update controls (MyTasksPage component)
- Prominent Clock-In/Clock-Out widget with real-time status display (ClockInWidget component)
- Work report submission form (SubmitReportPage component)
- Complaint submission form with title and description fields (SubmitComplaintPage component)
- Feedback submission form (SubmitFeedbackPage component)
- Personal allowances viewing interface (MyAllowancesPage component)
- Personal complaints tracking interface (MyComplaintsPage component)
- Personal feedback tracking interface (MyFeedbackPage component)
- Real-time chat interface with user search and conversation management (ChatPage component)
- Profile management with employment details (ProfilePage component)
- Personal settings configuration (SettingsPage component)

### 1.2.1.3. Authentication Interfaces

The system SHALL provide the following authentication-related interfaces:

- Login page with username/password form validation (Login component)
- Mandatory password reset interface for first-time login (ResetPasswordPage component)
- Forgot password request form with email input (ForgotPasswordPage component)
- Password reset confirmation page with token validation (PerformResetPage component)
- Automatic logout with token cleanup and Socket.io disconnection

### 1.2.1.4. Standard Interface Features

The system SHALL implement the following standard interface features:

- Horizontal navigation menu with role-based item visibility
- User avatar display with first character of first name or username
- Logout button with session cleanup functionality
- Form validation with real-time feedback using Ant Design Form components
- Responsive design adapting to desktop (1920x1080), tablet (768x1024), and mobile (375x667) screen sizes
- Loading states during asynchronous operations
- Error notification messages using Ant Design notification API
- Success confirmation messages for completed operations
- Protected routes with automatic redirection for unauthorized access
- Consistent padding and spacing (24px/48px) for content areas

## 1.2.2. Hardware Interfaces

### 1.2.2.1. Server-Side Hardware Requirements (Self-Hosted/On-Premise)

The system SHALL operate on server hardware meeting the following minimum specifications:

- **Processor:** Dual-core CPU at 2.0 GHz or higher (Intel Core i3/AMD Ryzen 3 equivalent or better) capable of concurrent Node.js process execution and PostgreSQL query processing
- **RAM:** Minimum 8GB DDR4 (16GB recommended for deployments exceeding 50 concurrent users)
- **Storage:** 
  - Minimum 50GB available storage space
  - SSD strongly recommended for PostgreSQL data directory to ensure sub-100ms query response times
  - Separate partition for database backups (minimum 20GB)
- **Network Interface:** 
  - Gigabit Ethernet adapter (1000 Mbps) for LAN connectivity
  - Server SHALL bind to all network interfaces (0.0.0.0) to enable mobile device access over LAN
  - Static IP address configuration recommended for consistent client connectivity
- **Operating System Support:** Linux (Ubuntu 20.04+/Debian 11+), Windows Server 2019+, or macOS 11+

### 1.2.2.2. Client-Side Hardware Requirements

The system SHALL be accessible from client devices meeting the following specifications:

- **Supported Devices:** 
  - Desktop computers (Windows, macOS, Linux)
  - Laptop computers
  - Tablets (iPad, Android tablets)
  - Smartphones (iOS 14+, Android 10+)
- **Display Requirements:** 
  - Minimum resolution: 1024x768 pixels
  - Recommended resolution: 1920x1080 pixels or higher
  - Touch-screen support for mobile devices
- **Network Requirements:** 
  - Active LAN connection (Ethernet or Wi-Fi) to reach server IP address
  - Minimum bandwidth: 1 Mbps per concurrent user
  - Network access to server ports: TCP 3000 (frontend), TCP 5001 (backend)
  - WebSocket protocol support (no proxy/firewall blocking)
- **Input Devices:** 
  - Keyboard and mouse/trackpad for desktop/laptop
  - Touch input for mobile devices
- **Browser Requirements:** 
  - Chrome 90+ (recommended)
  - Firefox 88+
  - Safari 14+ (macOS/iOS)
  - Microsoft Edge 90+
  - JavaScript enabled (required)
  - LocalStorage enabled (minimum 5MB quota)
  - Cookies enabled for session management

## 1.2.4. Communication Interfaces

### 1.2.4.1. REST API Interface

The system SHALL implement RESTful API communication using the following specifications:

**Protocol Specifications:**
- **Transport Protocol:** HTTP/1.1 (development), HTTPS/1.1 (production with reverse proxy)
- **Default Ports:** 
  - Backend API: TCP port 5001 (configurable via PORT environment variable)
  - Frontend: TCP port 3000 (development server)
- **Data Format:** JSON (JavaScript Object Notation) with UTF-8 encoding
- **Content-Type:** application/json for request and response bodies
- **CORS Configuration:** 
  - Allowed origin: Configurable via CORS_ORIGIN environment variable (default: http://localhost:3000)
  - Allowed methods: GET, POST, PUT, DELETE
  - Credentials: Supported for cookie-based sessions

**Authentication Mechanism:**
- **Method:** JWT (JSON Web Tokens) for stateless authentication
- **Token Format:** Bearer token in Authorization header
- **Header Format:** `Authorization: Bearer <jwt_token>`
- **Token Structure:** 
  - Header: Algorithm (HS256), Type (JWT)
  - Payload: user object (id, username, role), issued at (iat), expiration (exp)
  - Signature: HMAC SHA256 with JWT_SECRET
- **Token Expiration:** 1 hour from issuance
- **Token Storage:** Browser LocalStorage on client side

**API Endpoint Structure:**

| Endpoint | Methods | Purpose | Authentication | Authorization |
|----------|---------|---------|----------------|---------------|
| `/api/auth/login` | POST | User authentication | None | Public |
| `/api/auth/forgot-password` | POST | Password reset request | None | Public |
| `/api/auth/reset-password/:token` | POST | Password reset confirmation | None | Public |
| `/api/staff` | GET, POST, PUT, DELETE | User management | Required | Admin only |
| `/api/tasks` | GET, POST, PUT, DELETE | Task operations | Required | Manager (create), Staff (view/update) |
| `/api/attendance` | GET, POST | Clock in/out operations | Required | Staff (create), Manager (view all) |
| `/api/reports` | GET, POST | Work report submission | Required | Staff (create), Manager (view all) |
| `/api/complaints` | GET, POST, PUT | Complaint management | Required | Staff (create), Admin/Manager (view/respond) |
| `/api/feedback` | GET, POST, PUT | Feedback system | Required | Staff (create), Admin/Manager (view/respond) |
| `/api/allowances` | GET, POST, PUT, DELETE | Allowance management | Required | Manager (create/manage), Staff (view own) |
| `/api/chat` | GET, POST, PUT | Chat history operations | Required | All authenticated users |
| `/api/profile/me` | GET, PUT | Profile management | Required | All authenticated users |
| `/api/settings` | GET, PUT | Settings configuration | Required | All (personal), Admin (system-wide) |

**HTTP Status Codes:**
- 200 OK: Successful GET, PUT requests
- 201 Created: Successful POST requests
- 400 Bad Request: Invalid input data
- 401 Unauthorized: Missing or invalid JWT token
- 403 Forbidden: Insufficient role permissions
- 404 Not Found: Resource does not exist
- 409 Conflict: Unique constraint violation (duplicate username/email)
- 500 Internal Server Error: Server-side errors

**Request/Response Examples:**

```json
// Login Request
POST /api/auth/login
{
  "username": "admin",
  "password": "admin123"
}

// Login Response
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 1,
    "username": "admin",
    "role": "admin",
    "first_name": "System",
    "last_name": "Administrator"
  }
}
```

### 1.2.4.2. WebSocket Interface

The system SHALL implement real-time bidirectional communication using Socket.io with the following specifications:

**Protocol Specifications:**
- **Transport Protocol:** WebSocket (WS) for development, Secure WebSocket (WSS) for production
- **Fallback Transports:** Long-polling (automatic fallback if WebSocket unavailable)
- **Port:** Same as backend API (TCP 5001)
- **Connection URL:** `http://localhost:5001` (Socket.io automatically handles /socket.io path)

**Connection Lifecycle:**
1. Client establishes Socket.io connection
2. Client emits `authenticate` event with JWT token
3. Server verifies JWT and maps user ID to socket ID
4. Connection maintained for real-time events
5. On disconnect, server removes user-socket mapping

**WebSocket Events:**

| Event Name | Direction | Payload | Purpose | Authentication |
|------------|-----------|---------|---------|----------------|
| `connection` | Server → Client | socket object | Initial connection established | None |
| `authenticate` | Client → Server | JWT token string | Socket authentication | JWT verification |
| `send_message` | Client → Server | `{receiver_id, content}` | Send chat message | Required |
| `receive_message` | Server → Client | `{message, conversation}` | Receive chat message | Required |
| `disconnect` | Bidirectional | reason string | Connection termination | None |

**Event Payload Structures:**

```javascript
// authenticate event
socket.emit('authenticate', 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...');

// send_message event
socket.emit('send_message', {
  receiver_id: 5,
  content: "Hello, how are you?"
}, (response) => {
  // Callback with {status: 'ok'|'error', message, conversation}
});

// receive_message event (server to client)
socket.on('receive_message', (data) => {
  // data: {message: {...}, conversation: {...}}
});
```

**Connection Management:**
- In-memory user-socket mapping using JavaScript Map
- Automatic cleanup on disconnect
- Support for single active connection per user
- Reconnection handling with exponential backoff on client side

### 1.2.4.3. Database Communication Interface

The system SHALL communicate with PostgreSQL database using the following specifications:

**Connection Specifications:**
- **Protocol:** TCP/IP (PostgreSQL wire protocol version 3.0)
- **Port:** TCP port 5432 (default PostgreSQL port, configurable via DB_PORT)
- **Connection Method:** Connection pooling via pg (node-postgres) library
- **Pool Configuration:**
  - Managed by pg.Pool class
  - Automatic connection reuse
  - Error event handlers for unexpected disconnections
  - Graceful connection cleanup on application shutdown

**Connection Parameters:**
- **DB_HOST:** Database server hostname or IP address (default: localhost)
- **DB_PORT:** Database server port (default: 5432)
- **DB_DATABASE:** Database name (default: simple_workforce_manager)
- **DB_USER:** Database username (default: postgres)
- **DB_PASSWORD:** Database password (configured in .env)

**Query Interface:**
- **Method:** Parameterized queries to prevent SQL injection
- **Query Format:** `db.query(text, params)` where params is array of values
- **Example:** `db.query('SELECT * FROM users WHERE username = $1', [username])`
- **Transaction Support:** BEGIN, COMMIT, ROLLBACK for atomic operations
- **Error Handling:** Try-catch blocks with specific error messages for constraint violations

**Security Features:**
- SSL/TLS encryption support (configurable)
- Parameterized queries for all user inputs
- Database user with least-privilege access
- Connection string credentials stored in environment variables
- No hardcoded credentials in source code

### 1.2.4.4. Email Communication Interface

The system SHALL implement email communication for password reset functionality using the following specifications:

**SMTP Configuration:**
- **Library:** Nodemailer 7.0.10
- **Protocol:** SMTP (Simple Mail Transfer Protocol)
- **Default Configuration:** Ethereal Email test accounts (automatic creation)
- **Test SMTP Server:** smtp.ethereal.email
- **Port:** 587 (SMTP with STARTTLS)
- **Security:** TLS encryption (secure: false, STARTTLS enabled)

**Email Message Structure:**
- **From Address:** "Simple Workforce Manager" <no-reply@swm.com>
- **Subject:** "Password Reset Request"
- **Content Type:** HTML
- **Reset Link Format:** `${FRONTEND_URL}/reset-password/${token}`
- **Token Expiration:** 15 minutes from generation

**Production SMTP Configuration:**
The system SHALL support production SMTP servers via environment variables:
- SMTP_HOST: Mail server hostname
- SMTP_PORT: Mail server port (25, 465, 587)
- SMTP_SECURE: Boolean for SSL/TLS
- SMTP_USER: SMTP authentication username
- SMTP_PASS: SMTP authentication password

**Email Operations:**
- Password reset request email with time-limited token
- Preview URL generation for Ethereal test accounts
- Error handling for email delivery failures
- Asynchronous email sending to prevent blocking

**Example Email Content:**
